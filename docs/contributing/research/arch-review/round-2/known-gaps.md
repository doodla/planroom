# Architecture review round 2: known gaps

Findings each group of fixes left open, with the reason. One row per finding.

| ID | Title | Why it stays a gap |
|---|---|---|
| correctness-10 | Reconcile classes depend on where scan windows fall, and `handoff merge` doesn't reconcile itself | Applied in part: the first scan is now a baseline. Evaluating each change unit in topological order, or reconciling at the merge's own commits, changes the reconciler's core, and S4's CI path scans between the merges, so it passes as specified. |
| extensibility-3 | Several v0.1 questions are not pipelines of the fixed shapes, and S6 drift has no designed home | Downgraded. Machine pairing now has a home as pack data (DR-63). `drift`, `kinds`, `stage` and `lint` stay questions the composition root serves through `kernel::diff`, the catalogue and the plan lint; a `diff` or `meta` shape is a kernel change no scenario needs. |
| extensibility-5 | The domain-free check misses the coupling the design creates, and flags harmless generic words | E14 extends the scan to the contract only (DR-45). Rule types for MECE overlap, the MVP line and the ladder need the plan pack's prop schemas, which M1's plan slice designs, and an allow-list for generic words waits for a real false positive. |
| extensibility-6 | The pack schema has one-off tables and closed sets, and merge conflicts are unspecified | Applied in part: duplicate keys, overlapping globs, two default lenses, `Tier::Precise` and out-of-tree hint kinds are settled (DR-46). One generic `[[tables]]` in place of `[[languages]]`, `[[image_roles]]` and `[[stages]]` is a contract redesign that the next cross-pack built-in can justify. |
| extensibility-9 | Plan item types form a second kind system beside `[[kinds]]` | Making item types `[[kinds]]` that extend `kernel.item` reopens DR-45's plan model, and no v0.1 scenario needs another pack's Intent-level items. |
| extensibility-10 | Pack data carries no visual identity, and the canvas chooses views by lens ID | Applied in part: the canvas now picks a view by result type. Palette slots for a pack's lenses and kinds need design work in `design-language.md` and `@planroom/ui`, best done with the S10 evidence screenshots. |
| security-9 | The engine's checksum comes from the same release it verifies | Minor. Pinning per-target hashes in `engine.env` changes the release flow that operability-1 (E11) reworks, and it needs byte-reproducible archives proven across two separate builds first; the security table already states that checksums guard only against corruption. |
| cost-4 | Token sizing assumes 4 bytes per token, but Planroom's JSON measures about 2.2 | Downgraded. The always-on gate already projects real tokens through the measured ratio, and the 20% gates are relative, so the unit doesn't change what fails. Re-sizing the per-command budgets and the flat-tool estimate needs WS8's measured ratio over the real specs and envelopes. |
| unasked-9 | Hand-off merge is local-only with hooks off, which collides with PR-based and hook-enforced repos | Running the person's own hooks on the merge reopens DR-16's hooks-off rule and E15's refusal of repo-defined commands, and a `--via pr` mode needs push credentials that v0.1 keeps out of the engine. The merge's reply already names its undo. |
| unasked-3 | Large repos: unbounded history walk and an all-or-nothing scan under `process.run`'s timeout | Applied in part: the `git` extractor reads at most 5,000 commits and the mod runs `scan` with the 10-minute timeout (DR-47). Committing each repo's snapshot as it finishes would split the one scan transaction E3 relies on, a commit-cached history walk and a detached scan duty with progress frames are new store and mod machinery, and a generated 50k-file, 100k-commit repo in `first_run.rs` is a CI cost no tier A or B scenario needs. |
| unasked-8 | Workspace discovery misses common multi-repo layouts and allows silently nested workspaces | Applied in part: submodules, repos two levels down and a `workspace_nested` warning (DR-71). Merging the inner workspace's store on a card needs an import into a store that has authored events, which the event model doesn't define yet. |
| unasked-7 | `planroom open` has no path on WSL 2, SSH remotes, cloud sessions or headless Linux | Applied in part: `open` detects these hosts, opens through `wslview` on WSL and offers `/room share` (DR-29). Drawing the login URL in the pane for an SSH user puts a live code on screen and in scrollback, which DR-64 keeps out. |
| unasked-11 | "Remove Planroom" misses worktrees, the person key and user-level config | Applied in part: the guide lists every path, ref and config file in order, and hand-off clones replaced worktrees in DR-64. A `doctor --uninstall-plan` leaf is a new command; the ordered list serves until removal grows. |
| repo-4 | Any branch can satisfy the decision-record gate itself, and parallel branches collide on DR numbers | Applied in part: duplicate headings fail, numbers are assigned at merge, and a branch's merge lists its gated changes (DR-70). A hook that denies a branch's session the lock can't tell that session from the one that merges. |
| repo-7 | Navigation sends agents to about 115k tokens of design docs | Applied in part: the Read first table maps each area to its sections, records and scenarios (DR-70). An anchored index at the top of `architecture.md` would restate the heading outline GitHub already renders. |
