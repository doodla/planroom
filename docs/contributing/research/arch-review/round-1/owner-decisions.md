# Architecture review round 1: owner decisions

Round 1 ran nine review focuses, each with an independent verifier: 102 findings, 49 material and upheld, 5 downgraded, none refuted. The findings are in this directory, one JSON file per focus. These are the decisions on the cross-cutting questions. The fix pass applies them, then each finding's own proposed fix where no decision below overrides it.

## Write model and identity

- **D1. Writer instances, not actors, conflict.** The compare-and-set compares the writer instance `{actor, surface, client_id}`: a canvas tab ID, a mod session ID, an Artifact viewer, a CLI process. Two tabs of one person conflict like two people (correctness-2). The same-actor exemption applies only to the same writer instance.
- **D2. No TTY-based person detection** (security-3). A person at a terminal runs a person-only command through a confirmation read from `/dev/tty` that names the action, or through the mod's press. Bash agents must identify themselves: writes with no `PLANROOM_ACTOR` from a non-TTY process are `actor_required`. Reads need no actor, so an agent using only the plugin's tools and skills can still drive S1 and S2. The person key lives in the mod's `$.store`; `store.db` keeps only its hash.
- **D3. Accepting is a new write** (correctness-4). Accepting a ghost or choosing "yours" on a conflict writes a new `edit` that copies the fields, with `base` from the accepting view and `cause` set to the reviewed event, under the normal compare-and-set. Review events stay as the audit trail.
- **D4. A person's edit over a pending ghost supersedes the ghost** (correctness-1). The ghost is marked superseded and listed in Diffs; it raises no card. S8's stale write is person against person: the canvas tab against a mod press on the same field, two writer instances. Pin both cases in `cas.rs`.
- **D5. The reconciler's algorithm is specified and persisted** (correctness-3): the fact delta from the previous reconciled snapshot to the current head snapshots, attributed to non-merge commits (`git log --no-merges prev..head`) whose touched files intersect the facts' evidence paths. Ignore merge commits, including hand-off merges identified by the `planroom/KEY` second parent. Persist the outcome as a `reconcile` body on the scan event, so classes and "stays done" don't depend on scan timing.

## Data safety

- **D6. Nothing a person authored is ever only in one file.** After each person-authored commit (debounced), the engine appends the event export to a durable backup outside the working tree, under the data root (D16). When `.planroom/` is missing but a backup exists, `scan` deals one card, "Restore 214 edits from 2026-10-26?", with Yes pre-selected. Before any migration: `VACUUM INTO` a backup, keep the last 3, migrate plus a post-migration fold in one transaction, and roll back on failure. An older engine meeting a newer store says "restart this session to use vX" in one line instead of crash-looping. `planroom doctor --restore BACKUP` is the downgrade path. Detect filesystems where multi-process WAL is unsafe (network, sync folders, WSL `/mnt/*`) and put the store under the data root with a pointer file (unasked-5).

## Models, privacy and cost

- **D7. What leaves the machine is disclosed, consented and redacted.** Before the first billable call per workspace and provider, one card names the provider, what is sent and the expected cost. `kernel::redact` runs at the model boundary (every Jev state, Claude prompt and session-backend request file) and on mod tool outputs. The local CLI `--json` keeps raw `contains`, so the truth comparator still matches. Credential-bearing settings (`base_url`, `api_key_env`, backend choice) come only from user-level config or the environment, never from workspace config. `api_key_env` is an allow-list, and credentials go only to allow-listed hosts. A `.planroom/` directory that git tracks, or that the engine didn't create, is untrusted: its config isn't loaded and one card says so (security-1).
- **D8. Live model calls are opt-in.** An ambient proxy is never a credential unless `PLANROOM_LIVE_GATEWAY=1` (Claude) or `PLANROOM_LIVE_JEV=1` (Jev) is set. A real credential (`AI_GATEWAY_API_KEY`, `TYPESAFE_API_KEY`) is explicit and still goes through D7's consent card. `cargo xtask` and this repo's dev environment default to `PLANROOM_REPLAY=strict`. A test asserts zero outbound model requests with the proxy present and no flag (cost-1).
- **D9. Decisions prefill before they interrupt** (principles-2, unasked-6). Each decision kind declares `stakes`: `low` prefills (Jev's pick, or the kind's declared deterministic default with no model or budget), applied as an inferred fact with its confidence and listed in Decisions as one collapsed batch per kind ("12 dependencies pre-filled, review?"); `person` deals a card. `budget_exceeded` and `on_unavailable` fall back to the kind's default, never to an unpicked card. The first scan of a workspace deals at most 3 cards, batched by cause, plus at most one Jev setup card when no backend is configured. Cards-only kinds don't escalate to Claude up front (cost-7).
- **D20. Cost controls.** `part_relation` gets a deterministic candidate generator (at most 3 candidates per part) and produces inferred relations, not cards (cost-4). The always-on token gate measures the real surface: the first-turn usage delta of a headless session with and without the plugin, or `count_tokens` over the generated tool specs plus the prompt section and skill frontmatter, with sub-budgets (cost-5). One build-wide spend record, `docs/evidence/spend.jsonl`, appended by every live run and summed before each live call against the $3 cap; a user-level ledger shared across workspaces holds the daily cap (cost-2).

## Kernel, packs and extraction

- **D10. Intent is kernel vocabulary** (extensibility-1, option a). R14 makes Intent one of the five core ideas, so the kernel defines `kernel.project`, `kernel.item` and `kernel.touches`, as it defines `kernel.group`. The plan pack supplies stages, methods, prompts and lint on top. Machine checks take their prop names as shape parameters. PR thread status moves out of the `tree` shape into an artifacts-pack question step. The domain-free check scans for built-in pack kind and relation names, not only `pack.` prefixes.
- **D11. Languages are pack data** (extensibility-2): `[[languages]] id, extensions, line_comment` in `PackFile`. The code pack declares the built-in languages plus yaml and json; the Ruby pack declares `ruby`. The universal `files` extractor reads the merged table.
- **D12. S10's no-core-change check is restated now** (extensibility-3): scan only the shipped engine crates and `packs/` (not `xtask` or `testkit`) for the toy packs' identifiers, and prove binary identity: the same prebuilt binary, by sha256, runs S1 without the packs and S10 with them.
- **D13. Emit templates are typed** (extensibility-5): typed node props, and props on edges, coerced to the kind's declared prop schema.
- **D21. Extraction correctness:**
  - A metric-mention evidence source for comments, in the observability pack, that attaches evidence and never creates relations; "code, not prose" applies to relation creation (correctness-5).
  - A changelog extractor, and an `Evidence::Ref` variant for git-derived facts (correctness-6).
  - Leading-plus-trailing debounce with a maximum wait; `focus` skips inline rescans when a live process holds the scan lease; S8 and S13 measure commit to rendered (correctness-7).
  - A container `role` from declared image rules, so observability infrastructure is excluded from coverage (correctness-8).
  - Deterministic scan bounds instead of a wall clock, a per-blob fact cache, and no regression or scan-changed-under-edit from a partial scan (unasked-4).

## Surfaces, repo and operations

- **D14. Repo gates that actually fire** (repo-1 to repo-7): a per-commit decision-record gate with a committed `layout.lock` hash, `fetch-depth: 0` in CI, and a committed schema baseline instead of `origin/main`; a boundary self-test with a clean-copy control, an offline install in the copy and a realistic workspace-declared crossing; every CI job runs `cargo xtask <cmd>`, with a check that ci.yml has no other `run:` steps; `budgets.json` is a hand-ratcheted baseline, where raising a number needs a decision record in the same commit; a generated mod test harness (`target/mod-test/`) for `claude plugin test`; tests that need a live session move to evidence paths.
- **D15. Surfaces** (ux-1 to ux-5, principles-3, principles-5): importing inbox rows is person-only and leaves `room_change`; the band and `PaneModel.next` may point only at undoable, non-hand-off commands; `review` and `open` are catalogue commands; S9 counts real keys on scripted flows, with row hotkeys; `Transport` declares capabilities, and the Artifact shows engine-authored empty states for views it can't serve and applies `live/head` deltas; the pane has fallback states before the engine exists and outside a workspace; `handoff revert` undoes a merge, with `merged -> reverted` in the loop table, and `NotUndoable` is an enumerated list.
- **D16. One data root and a self-locating resolver** (operability-1 to operability-3): the resolver finds `engine.env` and the dev checkout from its own path; the data root is `${PLANROOM_DATA:-${XDG_DATA_HOME:-$HOME/.local/share}/planroom}`, shared by the mod, the Bash tool and agents. The canvas is embedded in the binary by `build.rs` from `target/canvas/` when present, with an engine-rendered fix page when absent. The source-build fallback builds from the checkout when the plugin is loaded from one, preflights the toolchain, and runs detached with a log.
- **D17. Local server auth without an ambient cookie** (security-7): the login code becomes an in-memory bearer token sent as a header; exact `Origin` on every request; a 128-bit code with a 60 s TTL; `.planroom/` is 0700 and its files 0600.
- **D18. Read tools stay inside the workspace** (security-4): `room_query` confines path arguments to the workspace's repos; outside paths go through `room_change`; credential paths are refused unless a person passes them.
- **D19. Out-of-tree packs are data but policy-bearing** (security-5): for any pack not embedded in the binary, `auto_enabled` is ignored until a person enables it with a card, and the first load of such a pack shows its kinds and prompt hashes in one card.
