# Contracts

This page lists every public contract Planroom has: what each one is, its single source, its version, what is generated from it, who consumes it, and the test that catches drift. It ends with Rust-style sketches of the core types. The sketches show shape and intent; the Rust types in `crates/contract/src/` are the source of truth once they exist, and this page links to them instead of restating them.

## Versioning rules

These rules apply to every contract below unless its row says otherwise [DR-37].

- **One source.** Every public shape is a Rust type in `planroom-contract`. Nothing else defines one. TypeScript types are generated; nobody hand-copies a type across the language boundary.
- **One schema in two views.** `cargo xtask gen` runs schemars 1.2.3 (draft 2020-12, `preserve_order`) and writes `schema/planroom.v1.schema.json` (the serialize view: what Planroom emits) and `schema/planroom.v1.input.schema.json` (the deserialize view: what Planroom accepts). Every contract is a `$defs` entry in them. `$id` is the raw GitHub URL on `main`.
- **One version.** `schema_version = 1` is the major version of the whole public contract: commands, flags, exit codes, the envelope, result types, the error object, events, files and the code tables. Additive changes keep it. A rename, a removal, a changed meaning, or a new required input field bumps it, and the schema file names with it.
- **Format tags.** Every persisted or exchanged document carries `format: "planroom.<name>/v1"`, so a file read out of context says what it is. The `/v1` follows `schema_version`.
- **Open sets.** Error codes, warning codes, node and relation kinds, event kinds, question IDs, hint kinds and command names are `anyOf: [{enum: [...]}, {pattern}]`, so an older reader still validates a newer value. Everything else is closed.
- **Readers of persisted documents** accept `format` versions up to their own and refuse newer ones with `schema_mismatch`. Unknown fields are kept through `#[serde(flatten)] extra` and written back unchanged.
- **Integers** stay below 2^53 (`seq`, counts, line numbers, byte sizes). Hashes and IDs are strings. A schema lint in `xtask` fails on a `uint64` without an annotation [rust-stack G8].
- **Breaking-change guard.** `cargo xtask check` compares the generated schema with `origin/main` and fails on a removed property, a removed enum value or a new required input field without a `schema_version` bump.

## Codegen flow

```text
crates/contract/src/*.rs ──schemars──▶ schema/planroom.v1.schema.json          ──json2ts──▶ packages/contract/src/generated/output.ts
                         ──schemars──▶ schema/planroom.v1.input.schema.json    ──json2ts──▶ packages/contract/src/generated/input.ts
contract::Command (catalogue) ──xtask──▶ packages/contract/src/generated/catalogue.ts (command names, ideas, actor rules, budgets,
                                         tool input schemas, ROOM_COMMANDS)
                              ──clap───▶ docs/reference/cli.md
contract::ErrorCode::ALL, WarningCode::ALL ──xtask──▶ docs/reference/errors.md (tables)
contract::PaneModel and $.state atoms ──xtask──▶ plugin/types/index.d.ts
crates/planroom/src/config/defaults.toml ──xtask──▶ docs/reference/configuration.md
boundaries.toml ──xtask──▶ .dependency-cruiser.cjs
```

`cargo xtask gen` writes every generated file; `cargo xtask check` regenerates each in memory and fails on any byte difference, with the regenerate command in the message. Every generated file starts with `GENERATED by cargo xtask gen. Do not edit.` (an HTML comment in Markdown, a `$comment` key in JSON schemas, a line comment in code). Generated directories are listed in [Repo layout](repo-layout.md#generated-directories).

## CLI JSON envelope

Every command with `--json` prints exactly one JSON document on stdout, on one line. Logs go to stderr. Text mode renders the same structs.

```rust
// crates/contract/src/envelope.rs
pub const SCHEMA_VERSION: u32 = 1;

pub struct Envelope<T> {
    pub schema_version: u32,                 // const 1
    pub ok: bool,
    pub command: CommandName,                // "ask", "handoff merge"
    #[serde(skip_serializing_if = "Option::is_none")] pub result: Option<T>,
    #[serde(skip_serializing_if = "Option::is_none")] pub error: Option<ErrorObject>,
    pub meta: Meta,
}

pub struct Meta {
    pub seq: Seq,                            // the store version this reply reflects; pass it back as `base`
    pub took_ms: u32,
    pub size: Size,                          // { bytes, tokens_est = ceil(bytes / 4) }
    pub next: Option<Cursor>,                // opaque: (seq, last_id, filter hash)
    pub truncated: bool,
    pub replayed: bool,                      // an idempotent replay of a stored reply
    pub warnings: Vec<Warning>,
    pub models: ModelUse,                    // { jev: Usage, claude: Usage } with calls, cache_hits, cost_usd
    pub model_requests: Vec<ModelRequestRef>,// session backend: requests the mod should fulfil
}

pub struct ErrorObject {
    pub code: ErrorCode,
    pub category: Category,                  // Usage | NotFound | Conflict | Permission | Budget | Unavailable | Failed | Internal
    pub retryable: bool,
    pub message: String,                     // one line, engine-authored
    pub hint: Option<String>,                // an exact command, such as "planroom show ev_01J..."
    pub details: serde_json::Value,          // per code, documented in the registry
}

pub struct Warning { pub code: WarningCode, pub message: String, pub details: serde_json::Value }

pub struct Handle { pub command: CommandName, pub args: Vec<String>, pub label: String }   // an exact invocation
pub struct Empty  { pub reason: EmptyReason, pub next: Handle }                          // no blank states
pub struct Listing<T> { pub summary: String, pub items: Vec<T>, pub empty: Option<Empty> }
```

### Error codes

`contract::ErrorCode` is the only place a code is spelled; a source scan fails on a code string anywhere else. Exit codes follow the category.

| Code | Category | Exit | Retryable | Meaning | `details` |
|---|---|---|---|---|---|
| `invalid_argument` | usage | 2 | no | bad flags or request | `field` |
| `ambiguous_ref` | usage | 2 | no | an ID suffix matched several records | `candidates` |
| `base_required` | usage | 2 | no | a write to user-authored state without `base` | `hint` names `meta.seq` |
| `workspace_not_found` | not_found | 3 | no | no repos at the path | `path` |
| `not_found` | not_found | 3 | no | unknown ID, question or file | `closest` |
| `stale_write` | conflict | 4 | after a re-read | a field changed since `base`; stored as a conflict, never merged | `event`, `base`, `theirs`, `yours`, `card` |
| `idempotency_mismatch` | conflict | 4 | no | the same `idem` with a different request | `idem`, `stored_event` |
| `already_resolved` | conflict | 4 | no | the card was already picked | `by`, `at`, `pick` |
| `handoff_conflict` | conflict | 4 | no | the merge preflight failed; every repo untouched | `repo`, `files` |
| `person_required` | permission | 5 | no | an agent ran a person-only command | `card` or `command` a person can run |
| `unauthorized` | permission | 5 | no | HTTP: missing cookie or a used login code | |
| `budget_exceeded` | budget | 6 | later | a spend or size guard stopped it; the work became a card | `guard`, `limit`, `spent` |
| `model_unavailable` | unavailable | 7 | yes | Jev or Claude unreachable; deterministic result returned with this as a warning, an error only for model-only commands | `provider` |
| `store_busy` | unavailable | 7 | yes | still locked after the 5 s busy timeout | |
| `schema_mismatch` | unavailable | 7 | no | the store or a file is from a newer version, or this process is older than the store | `found`, `supported` |
| `replay_missing` | unavailable | 7 | no | strict replay found no record (CI and tests) | `key`, `path` |
| `pack_invalid` | failed | 8 | no | a pack failed validation | `file`, `line`, `reference` |
| `git_failed` | failed | 8 | no | git exited non-zero; stderr redacted | `argv`, `stderr` |
| `internal` | internal | 70 | no | a bug | `report` (a path to a redacted report) |

Older readers map an unknown code to its category and exit code. A job or event recorded with a code this binary doesn't know reads as `internal` with `details.recorded_code`.

### Warning codes

| Code | Meaning |
|---|---|
| `claimed` | the target is claimed by someone else; `details {by, until}` |
| `truncated` | the result hit its budget; the summary and first page are kept |
| `unresolved_ref` | an alias or a linker join had zero or several candidates; no edge was made |
| `evidence_dropped` | an evidence item failed verification at ingest |
| `partial_parse` | a file parsed with error nodes; its facts are weak |
| `deterministic_fallback` | no model was reachable; deterministic tiers and cards with no pick |
| `inferred_unconfirmed` | the result includes inferred facts no person confirmed |
| `cache_regression` | an unchanged Claude prefix wrote the cache again inside its TTL |
| `scan_changed_under_edit` | a fact under a person's override changed; see Diffs |
| `stale_page` | a page cursor's `seq` is behind; unchanged rows have no gaps or duplicates |
| `model_request_pending` | the session backend is waiting for the mod |

## HTTP API and live stream

`planroom serve` binds `127.0.0.1:0` and writes `.planroom/serve.json` (mode 0600).

| Route | Request | Reply |
|---|---|---|
| `POST /api/v1/{command path, slash-joined}` | the command's request JSON, including `base` and `idem`; `Idempotency-Key` header accepted | the envelope; HTTP status by category: usage 400, not_found 404, conflict 409, permission 403 (`unauthorized` 401), budget 429, unavailable 503, failed 422, internal 500 |
| `GET /api/v1/stream?since=SEQ` | `Last-Event-ID` resumes | SSE with `event: <type>`, `id: <seq>`, `data: <StreamFrame JSON>` |
| `PUT /api/v1/layout` | `{view_key, structure_hash, positions}` | `204`; a cache, last-writer-wins |
| `POST /api/v1/session` | `{code}` from the URL fragment | `204` with an `HttpOnly`, `SameSite=Strict` cookie; a code works once |
| `POST /api/v1/drain` | `{token}` from `serve.json` | `202`; the server finishes in-flight requests and exits |
| `GET /`, `GET /assets/*` | | the canvas build from `<exe dir>/canvas/` |

## Store schema and migrations

- The DDL is in [Architecture](architecture.md#store-schema). The source is `crates/store/migrations/NNNN_name.sql`, applied in order by `PRAGMA user_version`, which equals `meta.store_version`.
- The store isn't a public contract: only `planroom-store` reads it. It's versioned because people keep stores across upgrades.
- A migration that touches `events` or `ledger` ships with `crates/store/tests/fixtures/store-vN.db` from the previous release and a test that opens it, migrates it and folds it.
- A binary that finds a newer `store_version` refuses with `schema_mismatch`. One that finds an older one migrates after asking any older `serve` to drain.
- `planroom export` writes NDJSON: a header line `{"format":"planroom.event/v1","workspace_id":...,"store_version":...}`, then one `Event` per line in `seq` order. `planroom import` of that file into a fresh store replays it.

## Graph model

```rust
// crates/contract/src/model.rs
pub struct NodeId(String);                   // "<namespace>:<kind-short>:<key>", such as "orders:pkg:internal/http"
pub struct EdgeId(String);                   // "e:" + 12 hex of sha256(kind ‖ from ‖ to ‖ via)
pub struct Kind(String);                     // "<pack>.<name>", such as "code.service"; "kernel.group", "kernel.external"
pub type Seq = u64;                          // below 2^53

pub struct Node {
    pub id: NodeId,
    pub kind: Kind,
    pub level: Level,
    pub parent: Option<NodeId>,              // exactly one parent; None only at the top
    pub name: String,
    pub aliases: Vec<String>,                // "host:orders", "service:orders", "pkg:@acme/kit", "endpoint:orders:POST /orders"
    pub props: BTreeMap<String, Value>,      // validated against the kind's prop schema
    pub layer: Layer,
    pub provenance: Provenance,
    pub evidence: Vec<Evidence>,
}

pub struct Edge {
    pub id: EdgeId,
    pub kind: Kind,                          // "code.http", "observability.watches"
    pub from: Ref, pub to: Ref,
```

## Extractor and linker contract

Built-in extractors and linkers implement Rust traits in `planroom-extract`. Pack authors use the declarative form above; both produce the same `FactBatch`.

```rust
// crates/extract/src/lib.rs
pub trait Extractor {
    fn name(&self) -> &'static str;
    fn run(&self, repo: &RepoView, files: &[RepoPath], opts: &Value) -> Result<FactBatch, ExtractError>;
}
pub trait Linker {                           // pure: the workspace's hints and nodes in, linked facts out
    fn name(&self) -> &'static str;
    fn link(&self, ws: &WorkspaceFacts, opts: &Value) -> Result<FactBatch, ExtractError>;
}
pub struct RepoView { pub name: String, pub root: PathBuf, pub commit: String, pub branch: String }
```

Rules checked by `extract/tests/contract.rs`: deterministic and sorted output; tolerant of error nodes; files over 1 MiB, binaries and ignored paths skipped; 2 s per extractor per repo; every fact has evidence whose `contains` verifies against the blob; code facts come from syntax nodes, never comments or docstrings; cross-file targets go out as aliases or hints; nothing from the repo runs.

## Mod tool schemas, state and the room family

The three tools come from the catalogue. Each tool's input is a discriminated union of its leaves' requests:

```json
{ "type": "object", "required": ["command"],
  "oneOf": [
    { "properties": { "command": { "const": "ask" },  "args": { "$ref": "#/$defs/AskReq" } } },
    { "properties": { "command": { "const": "map" },  "args": { "$ref": "#/$defs/MapReq" } } },
    { "properties": { "command": { "const": "...", "description": "..." } } }
  ] }
```

| Tool | Deferred | Leaves | Result |
|---|---|---|---|
| `room_query` | no | `focus`, `map`, `show`, `find`, `ask`, `diff`, `decide` (list), `who` | the envelope's `result` plus `meta.next`, `meta.seq` and warnings, as compact JSON |
| `room_change` | no | `scan`, `edit`, `intent` (not `version`), `claim`, `curate`, `decide --run`, `import` | the same; `base` defaults as in [Architecture](architecture.md#writes-actors-base-conflicts-and-retries) |
| `room_handoff` | yes | `handoff report`, `handoff collect`, `share` | the same |

### Mod state

The mod's state (`plugin/types/index.d.ts`, generated) is a set of `$.state` atoms under the plugin `planroom`, each a `Shaped<T>` of a contract type. They hold summaries only; the graph stays in SQLite.

| Atom | Type | Written by |
|---|---|---|
| `engine` | `{ path, version, backend, status }` | `session.start` |
| `pane` | `PaneModel` | the watch loop's debounced `focus` |
| `lastSeq` | `Seq` | the watch loop |
| `outbox` | `{ idem, argv, env_names }[]` (never the person key) | each write, cleared on reply |
| `agents` | `{ agentId, role, key, started_at }[]` | spawns and `turn.complete` |
| `remote` | `{ url, last_published_seq, last_sync_at }` | `/room share`, `/room sync` |
| `turnSeq` | `{ turnId, seq }` | `room_query` replies, for the default `base` |

### The room family

`ROOM_COMMANDS` in `catalogue.ts` lists every leaf with `room: true`, plus `/room` alone (focus the pane), `/room share` and `/room sync`. `/room help` prints it, and `room_commands_snapshot` pins it.

## Artifact db layout and event format

The page's manifest declares these capabilities [artifact-spike]:

```js
capabilities: {
  db: { rules: [
    { path: "", read: "view", write: "owner" },                 // snapshot heads and acks: only the session writes
    { path: "inbox", read: "interact", write: "owner" },
    { path: "inbox/{self}", read: "interact", write: "interact" }, // each viewer writes only their own inbox
  ] },
  user: { scopes: ["profile"] },
  sample: {},
}
```

| Path | Writer | Format | Size rule |
|---|---|---|---|
| `data/snapshot.json` (a published file, not `db`) | the session's publish | `planroom.snapshot/v1` | under 1 MB for the fixture; at most 16 MB |
| `live/head` | the session (`ArtifactData` with `if_version`), written last in each batch | `planroom.live-head/v1` | at most 256 KiB |
| `inbox/<uid>` | the viewer | `{ seq, updated_at }` | |
| `inbox/<uid>/events/<docId>` | the viewer (`collection.doc()` mints `docId`) | `planroom.inbox/v1` | deleted after import |
| `acks/<uid>` | the session | `{ imported_through, conflicts: [...] }` | one per viewer |

## Configuration

`.planroom/config.toml` is optional; every key has a default in `crates/planroom/src/config/defaults.toml`, and `PLANROOM_*` environment variables override keys. A new key needs a decision record saying why no default works [DR-22].

| Key | Default | Meaning |
|---|---|---|
| `packs` | `[]` | extra pack directories, after the built-ins |
| `models` | `auto` | `off` turns every Jev and Claude call off: deterministic tiers and cards with no pick (privacy, offline work, the models-off test path) |
| `[claude] backend` | `auto` | `auto` (gateway if a credential resolves, else session if a mod is attached, else off), `gateway`, `session`, `off` |
| `[claude] base_url` | `https://ai-gateway.vercel.sh` | |

## Plugin manifests

Owned by Claude Code; Planroom's tests check only what it relies on: `marketplace.json` names one plugin `planroom` with source `./plugin`; `plugin.json`'s `name` equals the marketplace entry; its `version` equals the Cargo workspace version, every `package.json` version and `plugin/scripts/engine.env`; `plugin/` holds no `bin/` and no symlinks; the icon is a square PNG of 512 to 2,048 px [mod-spike].

## Repo artifacts

These aren't product contracts, but tools and reviewers read them, so their shape is fixed here.

- **`budgets.json`** (generated): `{ "<scenario>.<question>": { "tool_tokens": N, "claude": { "prompt_total": N, "output": N, "cache_hit_rate": F } }, "fold.20k": { "ms": N } }`.
- **`feature_list.json`**: `{ "format": "planroom.feature-list/v1", "about", "fixture_note", "features": [{ id, title, tier (A, B or C), status, requirements, ci_path: { fixture, steps, compare, asserts, stand_ins }, evidence_path: { dir, steps }, tests, decision }] }`. `compare` names the `TRUTH.json` paths a step is checked against; `decision` (tier C only) names the record that added the entry. Status is `failing` or `passing`; a track sets `passing` only after the entry's tests pass.
